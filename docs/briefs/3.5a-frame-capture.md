# Brief 3.5a: reference frames from the original game

The capture half of milestone 3.5 of `docs/milestones.md`. The port's side (rendering the same
fixtures through `TSdlDC` and comparing, G4) follows when milestones 3.4 and 4.3 have a frame to
compare. Specification: `docs/specs/graphics.md` section 9 (frame oracle) in full, and
`testing.md` section 3 for the harness this builds on.

You work only in `D:\git\open-aow-private`: `tools/oracle` (the capture tool beside `run.py`,
`compare.py` and the copied `playtest.py`) and `tests/frames`. Read the private `AGENTS.md`.
Nothing in the product repository changes.

## Reference build

Capture from the original `AoW.exe` of the GOG install, not the rebuilt game section 9 names: the
rebuilt game equals the original (`D:\Build\oracle\README.md`), the original is the reference that
matters, and the recovery's symbol data (`D:\git\aow\data\symbols`, `data\signatures`) gives its
addresses, such as `TWindowsDC.BltSurface` in `Dcpack.dpl`. Use a disposable copy of the install
under `tools/oracle/obj` as the copied `playtest.py` does.

## Rules for native runs on this PC

The user works on this PC. Native runs are allowed with these conditions, and you check each one:

- Sound and music volume 0 through the harness's per-run registry setup, with the enable flags
  unchanged, and the game's registry key verified restored after every run.
- The game runs on the harness's hidden desktop, never on the user's desktop. If a capture needs
  the window visible to draw, stop and report instead.
- Processes are stopped only by the PID the harness recorded, never by name.
- If any run disturbs the user's desktop (a window or dialog appears on it), stop at once and report.

## What to build

1. `tools/oracle/frames.py`, as section 9 step 1 describes: a cdb breakpoint on the original's
   `TWindowsDC.BltSurface`, reading `FBack1`'s `Width`, `Height`, `Pitch` and `FBits` (bottom-up),
   `.writemem` of the bits, conversion to a top-down 555 image `frame-<n>.raw` with a JSON of size
   and frame number, captures conditioned on the frame number and on game state (`FDay`).
2. Scripted input for the fixtures that need clicks or a mouse position (scroll, open a city
   window, a unit info window, a spellbook page), through the debugger or window messages on the
   hidden desktop, deterministic from run to run.
3. `tests/frames/fixtures.toml` with the first set of section 9 step 2: the title scene at frame
   60, `small` day 1 at frames 1, 30 and 90 after load, the scrolled view, the city window, the
   unit info window, the spellbook page, and `heroes` at its first tactical combat frame, each with
   its window size, registry settings, mouse position and seed.
4. The reference frames recorded under `tests/frames/expected/` (private, never in the product),
   each also written as a PNG beside it for a person to look at, and a check that a second capture
   of every fixture is pixel-identical (so the capture is deterministic before it is a reference).

## Done measure

Every fixture of the first set is captured twice with identical pixels, the registry is restored
after every run, and no window or dialog appeared on the user's desktop. Report the fixtures, the
capture commands, any fixture that is not deterministic with the cause, and anything not done.
Keep a status file at `D:\git\open-aow-private\tools\obj\3.5a-status.md`.
