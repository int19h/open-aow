Milestone 9.1 of `docs/milestones.md`. Specification: `docs/specs/testing.md` section 3.2 step 4

## What to build

1. **Model mode** in `compare.py`: read both files into the property tree (the reader in
   `tools/oracle/asg.py`, extended where needed so that it covers every class and property of the
   shipped saves, maps and the oracle's autosaves) and compare trees: the same classes, the same
   property ids and values, the same children in the same order, with a report of the first
   differing node by its path in the format `compare_runs` uses. The byte mode stays and stays the
   default.
2. **Hash-ordered properties**: a list, in a file beside the comparator, of the properties whose
   children are written in hash-table order. Their children are compared as sets (by a key the
   list names per property) in model mode. The list starts empty, as `docs/design.md` section 5
   says, and the comparator prints which entries it applied.
3. **Floating point masks**: the same mechanism for the fields the user accepts as floating point
   divergence, also empty at the start.
4. **Agreement**: on every pair the byte mode calls equal, the model mode must also say equal, and
   on a pair the byte mode calls different, the model mode must name the same first difference or
   explain why it is a pure ordering or encoding difference. Prove it on the oracle runs and on
   deliberately altered saves (a swapped child order, a changed value, a reordered property table).
5. **`tools/check.py`** runs the oracle and the scenarios layers in model mode as well as in byte
   mode.
