## What to build

A probe is a Delphi 3 console program under `tests/probes/<name>.pas` that prints lines, one fact
per line. The expected output is what the oracle compiler's build of the probe prints. Later (brief
1.4) the transpiler turns the same probe into C# and the runner compares the two outputs line by
line. This brief builds the Delphi side: the runner's compile, run and store steps, the comparison
function, and the first ten probes.

### Files

- `tests/probes/run.py`: the runner (Python 3, standard library only).
- `tests/probes/<name>.pas` for `integers`, `floats`, `random`, `strings`, `format`, `sets`,
  `enums`, `records-layout`, `arrays`, `pointers`.
- `tests/probes/expected/<name>.txt`: the output of each probe as DCC32's program printed it,
  with LF line endings, and `tests/probes/expected/<name>.sha1`: the SHA-1 of the probe source
  that produced it.
- `tests/probes/README.md`: how to run, what a probe is, the output rules below, one line per
  probe saying what it covers.
- Nothing else. Build output goes under `tests/probes/build/`, which `.gitignore` excludes.

### The runner

`python tests/probes/run.py [name ...] [--force]`:

1. For each probe (all of `tests/probes/*.pas` when no name is given), compute the SHA-1 of the
   source. When `expected/<name>.txt` and `expected/<name>.sha1` exist and the hash matches, skip
   it unless `--force` is given.
2. Otherwise compile it with `C:\Tools\Delphi3\BIN\DCC32.EXE -CC -Q` into `tests/probes/build/`
   (`-E` for the executable directory, `-N` for the unit output directory, and `-U` for the RTL
   unit path under `C:\Tools\Delphi3\LIB` if the compiler does not find it alone). Find the flags
   that work and record them in the README. `D:\git\aow\tools\dcc_probe.py` shows how the recovery
   project drove the same compiler and is a reference, not something to copy wholesale.
3. Run the executable with its current directory set to `tests/probes/build/`, capture standard
   output, convert CRLF to LF, write `expected/<name>.txt` and `expected/<name>.sha1`.
4. A compile error, a non-zero exit code of the probe, or empty output fails that probe. The
   runner prints one line per probe (`ok`, `skipped`, `FAILED <reason>`) and exits non-zero when
   any probe failed.

`python tests/probes/run.py --compare <name> <file>` reads `expected/<name>.txt` and the given
file, compares them line by line, prints `match` or the first differing line number with both
texts, and exits 0 or 1. This is the comparison the transpile step uses in brief 1.4. Test it on an
expected file against itself and against a copy with one line changed.

### Output rules for every probe

- One fact per line in the form `label value`, where `label` is unique within the probe and names
  the fact (`div_neg7_2 -3`), so that a differing line names what differs.
- Nothing that varies between runs: no addresses, no times, no random values without a set seed.
  Pointer facts are printed as differences between addresses, never as addresses.
- ASCII only. A byte above 127 or below 32 is printed as its two-digit hex code through
  `IntToHex`, never raw. A string whose bytes matter is printed as hex pairs.
- Integers through `IntToStr` or `IntToHex`. A floating value is never printed through
  `FloatToStr` or `%f` and `%g`: it is scaled by a power of two stated in the label and truncated
  (`Trunc(x * 1048576)`), so that the expected text does not depend on float formatting.
- `{$APPTYPE CONSOLE}`, `WriteLn` to standard output, no units outside the Delphi 3 RTL
  (`SysUtils` and `Classes` are fine).
- Every probe ends with a line `end <count>` giving the number of lines before it.

### The ten probes

The rows of the table in `testing.md` section 2 are the content. For each probe the list of cases
there is the minimum, not the whole: add the edge cases you find while writing it, and say in the
README what you added. Specific notes:

- `integers`: include `shr` on negative `Integer`, `Shortint`, `Smallint`, `Byte` and `Word`
  overflow on `Inc` and `+`, `div` and `mod` for every sign combination, `Boolean(n)` for 0, 1, 2,
  255, `Ord(True)`.
- `floats`: `Round` on `x.5` for odd and even x, both signs, `Trunc`, `Int`, `Frac` for both signs,
  `/` on integers, with the scaled printing rule above.
- `random`: `RandSeed := 123456789`, then 1,000 values of `Random(n)` for n in 2, 6, 10, 100,
  1000, 65536 and 2147483647, with `RandSeed` printed after every call. Then 1,000 calls of
  `Random` into a variable `R`, printing `RandSeed` and `Trunc(R * 1048576)` after each.
- `strings`: every case of the table. The `AnsiCompareText` block is 65,536 lines, one per byte
  pair, `A B result` in hex, where result is the sign of the comparison. The probe prints this
  block last.
- `format`: `%s`, `%d`, `%x`, width, precision, `-`, `*`, explicit index, `%%`, and the errors
  (`EConvertError` for a bad argument type and for a missing argument), printing the exception
  class name.
- `sets`: sets of 8, 16, 32 and 256 elements, `Byte(S)` and `Word(S)` masks where the set fits,
  and the mask of a set over a subrange that does not start at 0 (`set of 8..15`, `set of 7..8`).
- `enums`: built from the five `enum_*.pas` files of `from-recovery/`: the same measurements as
  lines. If `{$Z1}`, `{$Z2}` and `{$Z4}` can be switched inside one program, measure all of them in
  it, otherwise measure the default and say so. `SizeOf` of each enumeration type and of records
  that contain them.
- `records-layout`: built from `from-recovery/layout.pas` and `layout_fields.txt`: the same
  quantities, each as a line `label value`, measured at run time (`SizeOf`, and
  `Integer(@R.Field) - Integer(@R)` for an offset). At least the 40 records of the table row.
- `arrays`: include a static array with a negative low bound, an array indexed by an enumeration
  and by `Char`, `High`, `Low` and `SizeOf` of each, open array parameters receiving a static
  array, a slice and an array constant, and a two-dimensional array's row-major order shown by
  offsets.
- `pointers`: `^T` dereference, `@` on variables, record fields and array elements, `Inc` and
  `Dec` on typed pointers and `PChar` (element size shown by address differences), `PChar`
  indexing, `GetMem` and `FreeMem`, `Move` and `FillChar` on records and arrays (contents printed
  afterwards), `nil` comparisons and `Assigned`, `SizeOf(Pointer)`, a record seen through a pointer
  to another record type at the same address (`PInteger(@Rec)^`), and the `Integer(P)` cast used
  only in differences.

## Done measure

1. `python tests/probes/run.py --force` compiles and runs all ten probes under DCC32, prints `ok`
   for each, and exits 0.
2. `python tests/probes/run.py` right after prints `skipped` for each and exits 0.
3. `python tests/probes/run.py --compare strings tests/probes/expected/strings.txt` prints
   `match`, and the same with a one-line change prints the differing line and exits 1.
4. The ten expected files exist, are ASCII, use LF, and each ends with its `end <count>` line
   whose count is right.

Report the output of all four, the DCC32 flags you settled on, every case you added beyond the
table, anything the compiler refused (with the error text), and anything you did not do.
