## The rule for this brief

Allocating a managed object (a list, a table, a buffer) counts as an operation that does not
throw: out of memory ends the process in the port. A body that inserts the object into its owner
and then allocates private children is therefore plain, as `TEResourceEditSettings` already is.
Any other operation after a publication or an acquisition that can throw (I/O, a lookup that
raises, a virtual call whose override can raise) makes the class context-guarded. If the survey
marks a group 1 class plain and you find such an operation, stop and report it with the line,
as the 9.3b-2 run did.

Keep ordinary virtual calls at their current positions, keep `base.X()` calls that stand for
Delphi `inherited` as non-virtual calls, and do not move work into field initializers.
