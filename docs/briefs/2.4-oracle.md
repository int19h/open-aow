# Brief 2.4: the port plays the original's game (O2, O3)

Milestone 2.4 of `docs/milestones.md`, measures O2 and O3 of `docs/specs/testing.md` section 3
(read 3.1 to 3.4 in full). The headless host plays 50 deterministic turns of Mountain Clash
(brief 2.3). Against the original's `small50-original-a`, day 01 is byte-equal and day 02 differs
in 600 leaves (`D:\git\open-aow-private\data\oracle\2.3-small-vs-original\`). This brief makes
the port's days equal the original's: first Mountain Clash for 50 turns, then the six other
scenarios for 20.

You work in `D:\git\open-aow` (`src/`) and `D:\git\open-aow-private` (`tools/`, `tests/probes`,
`data/oracle`). Read both `AGENTS.md` files and the 2.3 report in `data/oracle/2.3-report.md`.
The sandbox has no network (the usual `--no-restore` and `APPDATA` rules, no NuGet configuration
files). Regenerate `src/Generated` with the transpiler, never edit it.

## Method: find the first diverging call, not the first diverging byte

A save shows that a day differs, not where the play diverged. Use the random number stream,
which every game-logic decision consumes (`testing.md` 3.3: `TAoWHSMap.Random` loads and stores
`RandSeed` through `FDefendersSeed`).

1. **Port trace.** A host option `--trace-random <file>` logs every `TAoWHSMap.Random` call (and
   every other `System.Random` and `RandSeed` assignment the game logic reaches) with the frame,
   the argument, the result, `RandSeed` before and after, and the Delphi source location of the
   caller (the generated method's `// <file>.pas:<line>` comment, or a call-stack walk). It is a
   host service or an override hook, not an edit of generated code, and it costs nothing when off.
2. **Original trace.** The same log from the original game under the recovery's harness:
   `D:\git\aow\tools\playtest.py` runs the original `AoW.exe` from a copy of the GOG game under
   `C:\Tools\cdb_x86\cdb.exe` with breakpoints. Add a breakpoint on the original's
   `TAoWHSMap.Random` that echoes the argument, the result and `RandSeed`, with `kb` frames or the
   return address resolved through the recovery's symbol data (`D:\git\aow\data\symbols\`,
   `data\signatures\`). Do this in a copy of `playtest.py` under `tools/oracle/` (the recovery's
   file is read only), run `small` for two days, and keep the trace under `tools/oracle/obj`. If
   the harness cannot run from the sandbox (the hidden desktop, the debugger or the registry
   redirection fail), stop at once and report the exact command and error: the design session
   runs it outside the sandbox.
3. **Bisect.** Compare the two traces call by call. The first call whose argument, result or
   caller differs names the first diverging routine. Find the cause in the transpiler, the shim or
   an override, fix it there with a probe or test that pins it, regenerate, rerun, and repeat
   until the traces agree to the end of day 02, then day 51.
4. Divergences the trace cannot show (a state difference that reaches no `Random` call before the
   save) go through the save comparison: the changed leaves of the first differing day, read
   against the code that writes them.

## The other scenarios

When `small` matches for 50 turns, run `large`, `underground`, `large_igor`, `heroes`, `magic`
and `water` for 20 turns against their original runs (the labels are in `D:\Build\oracle\README.md`),
with the same method. The runs with harness flags (`--tactical --tactical-battles 3
--exercise-items` on `heroes`, `--global-spell 46` on `magic`) are compared from day 01 to the
first day a flag acts unless the host reproduces the flag, as `testing.md` 3.1 says. Read those
flags in `playtest.py` and reproduce the ones the host can.

## Done measure

1. Both solutions build with zero warnings, tests pass, probes match, and O1 still holds.
2. O2: the port's `small` run equals `small50-original-a` on every day to day 51, by `compare.py`
   with only the inflation and `$37`, `$3A`.
3. O3: the six other scenarios equal their original runs for 20 turns, or, for a scenario that

   what is known about its cause.
4. Every difference that turns out to be floating point (`docs/design.md` section 5 accepts it)
   is reported with the evidence (the double expression, the x87 result, the C# result) and not
   masked: the design session decides each mask.
