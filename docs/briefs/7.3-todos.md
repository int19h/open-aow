# Brief 7.3: the remaining TODOs, classified and paid off where play reaches them

Part of milestone 7 of `docs/milestones.md`. The emitted code has 506 TODOs: places where the
generated code throws until an override replaces it (`transpiler.md` section 9 item 2). Scripted
paths and oracle runs pay them off as they reach them, which leaves the unreached ones unknown.
This brief finds out which ones a single-player game can reach and pays those off.

You work in your product worktree (named in the prompt) and in `D:\git\open-aow-private` under
`tools/transpile` and `tests/probes`. Read both `AGENTS.md` files. Another session (brief 7.4)
works in the main checkout at the same time and changes overrides there: keep your changes to the
override manifest in separate, clearly named entries, so that the design session can merge both.

## What to do

1. **Classify every TODO** with its location, its cause (the report's rule) and a reachability
   class, computed from the resolved call graph of the transpiler with the game's entry points as
   roots (startup, the frame loop, the window manager's handlers, the AI and turn processing, the
   load and save path): `game` (reachable in single-player play), `editor` (reachable only from
   editor units or design-time code), `network` (multiplayer, e-mail and DirectPlay paths, which
   stay stand-ins in the first release), `platform` (a boundary the SDL host or the shim owns), or
   `dead` (no path from the roots). A virtual call counts as reaching every override of its slot.
   Write the classification to `D:\git\open-aow-private\data\transpile\todos.md` and `todos.json`.
2. **Pay off the `game` class**: an override from the Delphi source (or a transpiler fix where the
   cause is a mapping rule), each with a test or a probe that pins the behavior, and the transpiled
   probes and oracle still passing. Where a TODO's original behavior cannot be determined from the
   source and the recovery's notes, list it with what is missing.
3. **`platform`** TODOs: implement the ones the SDL host or the shim already has the service for,
   and list the rest with the service they need.

## Done measure

The classification covers all TODOs. The `game` class is zero or every remaining one is listed
with its reason. `python tools/check.py --product <your worktree>` passes (add the option if the
script lacks it). Report the counts per class before and after, and anything not done. Keep a
status file at `D:\git\open-aow-private\tools\obj\7.3-status.md`.
