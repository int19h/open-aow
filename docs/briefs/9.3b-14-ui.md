## Scope

Every user-interface component class with a split initializer or a guarded static factory: classes
that descend from `Component` (Delphi `TComponent`) or `Control` (Delphi `TControl`) in `src/Units` (windows, panels, buttons, labels, grids,
menus, list, edit and combo controls, tool tips, scroll bars, gauges, memos, the map controls), and
every data module and inherit-only control that `src/Layout/ComponentConstruction.cs` still gives a
forwarding owner constructor. Other briefs own the classes already converted, and the engine classes
(`EObject` descendants) are out of scope.

List every class in scope first in the status file with its bodies and the shape the rule gives
it.

- **Plain:** the body only assigns fields, allocates private children, or calls virtual methods
  whose overrides do the same.
- **Context-guarded:** the body publishes the object (owner insertion is already done by
  `EObject`, so this means a further list, cache, global or registry) or acquires something its
  `Destroy` releases, and later work on the chain can throw.
- **Not converted:** anything that fits neither cleanly (work before the base body that the base
  observes, a skipped base initializer, reentry on an existing object, a raw `NewInstance`
  consumer). Leave such a class as it is, list it in the report with the line and the reason, and
  continue with the rest. Do not stop the run for it.

Follow the layout construction decision in `ctor-design.md` ("Layout construction decision (Fable,
after 9.3b-6)"). UI components get no context guard: their bodies after owner insertion only assign
fields and allocate lists. A class whose body does more after insertion (a resource link released in
`Destroy`, I/O) is listed and handled by the family rule. Each converted class gets a real
`TFoo(Component AOwner)` constructor (or its own existing signature) chaining to its base, so layout
code reaches it as `new TFoo(this)`. Inherit-only classes get a forwarding constructor in their own
unit source, not in `ComponentConstruction.cs`. When the classes are converted, regenerate the layout
files with the private emitter, which then stops emitting the forwarding constructors, as
`D:\git\open-aow-private\tools\forms\README.md` describes: build
`tools\forms\Model` and `tools\forms\Generator`, run the Model tool with the recovered Delphi
source, `C:/Tools/Delphi3/SOURCE`, your worktree's `src\Units` and an output `model.json` under
`tools\obj`, then the Generator into a scratch folder under `tools\obj`, and copy the emitted files
over your worktree's `src\Layout`. Never edit layout files by hand. Report the regenerated diff
summary. `ComponentConstruction.cs` keeps only what the emitter still needs.

Keep ordinary virtual calls at their current positions and `base.X()` calls that stand for Delphi
`inherited` as non-virtual calls. Do not move work into field initializers. A parameterless
constructor stays only for a named raw consumer. Callers inside your worktree use `new` or the
guarded factory. Callers in the private repository are listed in the report with a ready patch.
A static factory with a `new` modifier that no longer hides anything loses the modifier. Do not
add warning pragmas.
