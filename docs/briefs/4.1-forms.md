# Brief 4.1: the form reader, the generated tables and the module load (U1, U2)

Milestones 4.1 and 4.2 of `docs/milestones.md`. Specification: `docs/specs/ui-layout.md` in full,
with the change of 2026-10-26 in its section 1: the port reads the 79 form resources from the
user's `AoW.exe` at run time, not from text files in the product. Read `parallel-tracks.md` in
this folder first.

You write in your product worktree under `src/Forms` (the reader and the loader) and in the
private repository under `tools/forms` and `tests/forms`.

## What to build

1. A reader for the binary form resources (`RT_RCDATA` resources of `AoW.exe` with the `TPF0`
   signature, the format Delphi 3's `TReader` streams, `C:\Tools\Delphi3\SOURCE\VCL\CLASSES.PAS`),
   producing the tree section 3 describes for the text grammar: objects, properties with their
   value types, string lists, sets, binary blocks, `#nnn` characters. A small PE resource reader
   finds the resources. The text grammar of section 3 is also read, for data mods that supply a
   text form in place of a resource.
2. The generated property, class and handler tables of section 5. The transpiler is frozen, so
   write the generator as a separate tool under `tools/forms` that reads the transpiler's resolved
   model through its command line (the `resolve --dump` output or a new read-only command added
   to the tools project in `tools/forms`, never in `tools/transpile`), and writes the tables as C#
   into `src/Forms/Tables`. Say in the report if the transpiler needs to emit them itself later.
3. The loader of section 4: the 77 modules in the `Application.CreateForm` order, the VCL fixup
   rules, translators.
4. `tools/forms/check.py` and `dump.py` of section 8, over the recovery's text files
   (`D:\git\aow\data\forms\AoW`), and a check that the binary reader's tree equals the text file's
   tree for all 79 forms. `tests/forms/` in the private repository holds the expected trees.
