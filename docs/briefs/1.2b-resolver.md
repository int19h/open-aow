## What to build

A resolver stage that takes the parsed units of the transpile set and the parsed interface
sections of the RTL, VCL and import units, and produces a typed tree: every identifier use bound
to its declaration, every expression with its static type.

### Symbols and scopes

- A symbol table per unit: interface and implementation sections, with Delphi's visibility (the
  implementation sees the interface, other units see only the interface). The `System` unit is
  implicitly used first by every unit, and `SysInit` where Delphi 3 does.
- Scopes in Delphi's order, innermost first: the current routine's locals and parameters,
  `Result`, the enclosing routines (nested routines see their parents' locals), `with` expressions
  innermost first, the class of a method and its ancestors (`Self` implicit), the current unit,
  then the units of the `uses` clauses from last to first (`transpiler.md` section 3).
- Class members: fields, methods, properties, with inheritance and forward class declarations.
  `private` and `protected` are visible across the declaring unit.
- Overloading does not exist in Delphi 3, so one name in one scope is one declaration. Two
  declarations of one name in one scope are an error with both locations.

### Types and expressions

- Every type form the parser knows, with type identity as Delphi defines it (`type T = Integer` is
  an alias, `type T = type Integer` is a new type).
- Every expression gets a static type: literals (with Delphi's rules for integer literal types and
  `Char` versus string constants), operators with Delphi 3's result types (integer arithmetic in
  `Integer`, `Cardinal` mixing, real arithmetic in `Extended`, set operators, string `+` producing
  `string`, comparisons producing `Boolean`), function calls, typecasts written as calls (`T(x)`,
  told apart from calls by the callee being a type), `@`, `^`, `is`, `as`, indexing (arrays,
  strings, default array properties, `PChar`), field and property access, set constructors.
- Names used without parentheses are classified: a variable, a constant, a type, a routine call
  with no arguments, a method pointer value (when assigned to a procedural type), a property read.
  This is the decision the parser left open.
- `with E do S`: record, for every name in `S` that resolves to a member of `E`, which `with`
  level bound it. The emitter needs this (`transpiler.md` section 5.2).
- `inherited` with and without a name, resolved to the ancestor's method.
- Constant expressions evaluated where Delphi needs them (array bounds, subrange bounds, set
  element ranges, `case` labels, typed constant initializers), with `SizeOf`, `Ord`, `Low`,
  `High`, `Chr`, `Succ`, `Pred` in constant position.
- Built-in routines (`Inc`, `Dec`, `Length`, `SetLength`, `Copy`, `Assigned`, `New`, `Dispose`,
  `Exit`, `Break`, `Continue`, `Move`, `FillChar`, `Write`, `WriteLn` and the rest of the
  compiler magic of `SYSTEM.PAS`) typed by their Delphi rules, not by their RTL declarations.

### Errors and the command

- An identifier that no scope resolves is an error with `file:line:col`. So is a type mismatch the
  resolver can decide (assigning a class to an integer). Type compatibility rules beyond what the
  source needs are not required: where the resolver cannot decide, it accepts and records nothing.
- `dotnet run --project tools/transpile/Transpiler -- resolve --source D:\git\aow\src\delphi3
  --rtl C:\Tools\Delphi3\SOURCE [--unit <name>] [--dump <file>]` runs parse and resolve over the
  transpile set and prints one line per unit (`ok` or the error count and the first error), the
  list of unresolved identifiers grouped by name with counts, and a summary. Exit code 0 when
  there is no error. `--dump` writes, for the units resolved, every identifier use with its
  location, the declaration it bound to (unit, scope, location) and the expression type, one per
  line, sorted, for review.
- Inside a member that `D:\git\open-aow\src\Overrides\overrides.toml` lists, errors are counted
  separately and do not fail the run (the file does not exist yet: a missing file means no
  overrides).

## Tests

In `tools/transpile/Transpiler.Tests/`, small Delphi snippets with assertions on the binding and
type of named uses: `uses` order shadowing, unit qualification, nested routine access to parent
locals, `with` over a record and a class with a shadowed local, `with A, B`, `Self` implicit in
methods, inherited members across units, private access from a unit routine, forward class
declarations, `Result` and the function name as result variable, properties with getters and
`index`, default array properties, class methods and `class of`, procedural types and method
pointers (a routine name as a value versus a call), typecasts versus calls, constant expression
evaluation, `case` labels of `Char` and enumeration type, the built-in routines.
