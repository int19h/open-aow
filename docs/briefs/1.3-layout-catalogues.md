# Brief 1.3: the layout model, the catalogues and the idiom resolution

Milestone 1.3 of `docs/milestones.md`. Specification: `docs/specs/transpiler.md` section 1 (the
five catalogue inputs), section 4.2 (enumeration and set storage), section 4.3 (the layout rules
and the record decisions), section 4.8 (initialization order), section 6 (the normalization rules
N1 to N12), section 8.2 (assembler routines) and section 9 item 10 (the catalogue checks). Read
them first, in `D:\git\open-aow\docs\specs\`, then the resolver of brief 1.2b under
`D:\git\open-aow-private\tools\transpile\Transpiler\`.

You work in `D:\git\open-aow-private`. Its `AGENTS.md` holds the standing rules. Write only under
`tools/transpile/`. The sandbox has no network and the packages are restored: add no package.
`System.Text.Json` is in the framework. Run the tests with `dotnet test` from `tools/transpile`.

## Inputs

## What to build

1. **Layout model.** From the resolved declarations, compute `SizeOf`, alignment and every field
   offset of every record type, and the instance size and field offsets of every class, by the
   rules of `transpiler.md` section 4.3, with enumeration and set storage by section 4.2. Replace
   the resolver's deferred `SizeOf` constants with the computed values, so that constant
   expressions using `SizeOf` fold.
2. **Catalogue loading.** Typed readers for the six files, with a clear error when a file is
   missing or its shape is not the expected one.
3. **Idiom resolution, rules N1 to N12 of section 6.** For every occurrence in the transpile set,
   detect it in the typed tree and compute its resolution as section 6 defines, by the
   transpiler's own analysis: N3 by byte offset in the view through the layout model, then the
   field at that offset of the run-time class in `class-layouts.json` (or the virtual slot in
   `classes.json` for a method view), with the receiver narrowing section 6 and section 4.4
   describe. Record each resolution on the tree (an annotation the emitter of a later brief
   reads), not as rewritten source text. Detection and resolution only: no emission.
4. **Catalogue checks, section 9 item 10.** Compare the transpiler's own results with the
   catalogues: every layout view resolution against `layout-views.json` at the same file and line,
   every shape cast, cell view, pointer-view constant, self-assignment and `absolute` alias found
   against `shape-casts.json` (in both directions: found and not listed, listed and not found),
   every class layout (instance size and field offsets) against `class-layouts.json`, every
   transpiled unit with an `initialization` section against the `AoW.exe` table of
   `initialization-order.json`, and every assembler routine of a transpiled unit against
   `asm-routines.json` (present, same kind of declaration).
5. **Initialization order.** Compute the `InitializeAll` order of section 4.8 from the `AoW.exe`
   entries, with the four null entries skipped and reported.
6. **The command.** `dotnet run --project tools/transpile/Transpiler -- check --source
   D:\git\aow\src\delphi3 --rtl C:\Tools\Delphi3\SOURCE --data D:\git\aow\data --port-data
   D:\git\open-aow-private\data [--report <file>]` runs parse, resolve, layout, resolution and the
   checks, prints a count per check and per rule, and writes a Markdown report with every
   disagreement (`file:line`, what the transpiler found, what the catalogue says) and every
   resolution per rule. Exit code 0 when there is no disagreement.

A disagreement is reported, never silently resolved in favor of either side. Where the
transpiler's analysis is wrong, fix the analysis. Where you are convinced a catalogue entry is
wrong, keep the disagreement in the report with your evidence: the design session decides, and
the catalogue belongs to the recovery project.

## Tests

- The layout model reproduces every line of `records-layout.txt` and the size lines of
  `enums.txt` (build the same declarations from the probe source through the parser and the
  resolver, compute, compare, and name the probe label in a failure).
- One test per rule N1 to N12 on a small snippet, including the `TLeaderSetupView` swap of section
  6 N3 and a method view call resolved by slot.
- The initialization order of a small three-unit case, and the reading of the real `AoW.exe` table
  (327 entries, 4 null).

## Done measure

1. `dotnet build` and `dotnet test` in `tools/transpile` pass with zero warnings.
2. The `records-layout` probe passes against the model: every `SizeOf` and offset line of the
   recording.
3. The `check` command over the whole transpile set reports zero disagreements and exits 0, or
   every remaining disagreement is listed in the report with evidence that the catalogue entry is
   wrong (stop and report rather than bending the analysis to agree).
4. Counts per rule N1 to N12 in the report, compared with the counts in section 6's table, with a
   line of explanation for every rule whose count differs.

Report the outputs, the counts, every disagreement left with its evidence, and anything not done.
