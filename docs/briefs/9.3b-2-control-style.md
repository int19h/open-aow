## The family

The closure is four classes, converted together or not at all, so that no `base.Create__init`
runs under a real constructor:

- `Engine.ControlStyleObject` (Delphi `TEControlStyleObject`) (`src/Units/Engine.cs`, near line 9353)
- `Engine.ResourceEditSettings` (Delphi `TEResourceEditSettings`) (near line 9758)
- `AoWE.PadControl` (Delphi `TPadControl`) and `AoWE.FlagControl` (Delphi `TFlagControl`) (`src/Units/AoWE.cs`, near lines 52162 and 52293)

Three of the four get plain constructors under the rule: their bodies only assign fields and
set the control style. `FlagControl` gets a context-guarded constructor. Its body links
`Flags.ILB` through the owner's image library manager, and its `Destroy` releases it. The disk
list's `LinkToImageLibrary` (`src/Units/ImageLib.cs`, near line 7614) adds one to the library's reference
count and then rethrows when loading the file fails. Today the guarded factory then runs `Destroy`,
whose `ReleaseImageLibrary` takes the count back down. The context keeps that. This is the first family that
uses `Aow.Rtl.ConstructionContext`.

`FlagControl` requires its owner to be the game set (`AoWHSSet` (Delphi `TAoWHSSet`)). The routes that pass nil
(`EngineObject.Copy` and the binary saved-ID route) never reach `FlagControl` in the game: no copy of
it and no distinct saved class entry exists (the audit is in `tools\obj\9.3b-2-status.md`). A
nil owner faults before the link. Today the guarded factory then releases a link that was never
made, and the converted constructor does not. That difference is unreachable and is recorded in
`ctor-progress.md`.

## What to do

1. **`EngineObject` gets a semantic constructor beside the raw route.** Add a protected
   `EngineObject(ECustomNode AOwner)` that runs the body of today's `EngineObject.Create__init`, at the
   same point relative to everything else, including the virtual `SetOwner` call. The existing
   `Create__init` and the converted constructor share one non-virtual body helper, so a converted
   chain runs it once and a legacy chain runs it once. The parameterless constructor stays for the
   unconverted descendants and the raw consumers.
2. **The context on the `FlagControl` chain.** `EngineObject` also gets a protected
   `EngineObject(ConstructionContext? context, ECustomNode AOwner)` that captures `this` when the
   context is present, before anything else, and then runs the same body. The one-argument
   constructor calls it with nil. `ControlStyleObject` carries the same two overloads, because
   `FlagControl`'s chain passes through it. `FlagControl`'s constructor is private or protected,
   takes the context, and its public creation is a static factory over
   `ConstructionContext.Create`. Add the overload
   `Create<TArg, T>(TArg arg, Func<ConstructionContext, TArg, T> construct)` to the context so the
   factory and the registry entry are static lambdas without a closure.
3. **The four classes get real constructors** `(ECustomNode AOwner) : base(AOwner)` with the
   bodies of their initializers and their `// Unit.pas:line` comments. Keep
   `base.GetControlStyle()` as a non-virtual call (Delphi `inherited`). Their `Create__init`
   overrides, static `Create` factories and `Meta.Create` overrides with the guarded allocation go.
   A class whose parameterless constructor no raw consumer needs loses it. A remaining one is named
   with its consumer.
4. **Typed creation.** Add a completed-object creation entry for `EngineObject` types beside `Meta`,
   of type `Func<ECustomNode, EngineObject>`, held in the registry with the type. For the four classes
   it is `owner => new TFoo(owner)` for the plain three and the guarded factory for `FlagControl`. `EngineObject.Meta.Create(owner)` for a type with a typed entry
   calls that entry. For every other type it keeps the guarded split path. There is no cycle
   between the facade and the entry.
5. **Registrations.** The three allocation delegates in `src/Units/MetaRegistry.cs` (lines 114,
   199, 227 and 300 today, for `ControlStyleObject`, `FlagControl`, `PadControl` and
   `ResourceEditSettings`) change in this brief to register the typed entry. Class IDs, `Meta`
   singletons and class metadata do not change.
6. **Callers.** The two direct callers in `AoWE.cs` (`PadControl.Create(this)` and
   `FlagControl.Create(this)`) use `new` and the guarded factory.

## Tests

In `src/Rtl.Tests` or the product tests, whichever already reaches `Aow.Units`, assert for each of
the four classes:

- exact runtime type and owner through `new`, through `Meta.Create` on its class reference,
  through `EngineObject.Copy`, and through the engine's creation by saved class ID (`CreateEngineObject`).
  The three classes that accept a nil owner are tested with nil and non-nil owners.
  `FlagControl` is tested with a game-set owner through the routes the game uses.
- `FlagControl`'s `Flags.ILB` reference count after creation, after `Destroy`, and after a
  creation whose library load fails (a disk-list entry whose file is missing or corrupt) equals
  today's. Pin these counts on main first, then keep them. This is the context's first proof on a
  game family.
- the `EngineObject` body runs once on a converted chain and once on a legacy chain (one test class
  on each side is enough)
- a binary read that fails after successful construction of one of the four (truncated stream)
  behaves as it does today: the same exception, and the owner's children afterwards as today. Pin
  today's behavior on main first, then keep it.
