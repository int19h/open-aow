## The family

The closure is four classes, converted together or not at all, so that no `base.Create__init`
runs under a real constructor:

- `Engine.TEControlStyleObject` (`src/Units/Engine.cs`, near line 9353)
- `Engine.TEResourceEditSettings` (near line 9758)
- `AoWE.TPadControl` and `AoWE.TFlagControl` (`src/Units/AoWE.cs`, near lines 52162 and 52293)

Under the rule their bodies only assign fields and call `GetControlStyle`, so they get plain
constructors. Confirm this for each body and say so in the report. If a body publishes the
object or acquires a released resource beyond what `TEObject` already does, stop and report.

## What to do

1. **`TEObject` gets a semantic constructor beside the raw route.** Add a protected
   `TEObject(TECustomNode AOwner)` that runs the body of today's `TEObject.Create__init`, at the
   same point relative to everything else, including the virtual `SetOwner` call. The existing
   `Create__init` and the converted constructor share one non-virtual body helper, so a converted
   chain runs it once and a legacy chain runs it once. The parameterless constructor stays for the
   unconverted descendants and the raw consumers.
2. **The four classes get real constructors** `(TECustomNode AOwner) : base(AOwner)` with the
   bodies of their initializers and their `// Unit.pas:line` comments. Keep
   `base.GetControlStyle()` as a non-virtual call (Delphi `inherited`). Their `Create__init`
   overrides, static `Create` factories and `Meta.Create` overrides with the guarded allocation go.
   A class whose parameterless constructor no raw consumer needs loses it. A remaining one is named
   with its consumer.
3. **Typed creation.** Add a completed-object creation entry for `TEObject` types beside `Meta`,
   of type `Func<TECustomNode, TEObject>`, held in the registry with the type. For the four classes
   it is `owner => new TFoo(owner)`. `TEObject.Meta.Create(owner)` for a type with a typed entry
   calls that entry. For every other type it keeps the guarded split path. There is no cycle
   between the facade and the entry.
4. **Registrations.** The three allocation delegates in `src/Units/MetaRegistry.cs` (lines 114,
   199, 227 and 300 today, for `TEControlStyleObject`, `TFlagControl`, `TPadControl` and
   `TEResourceEditSettings`) change in this brief to register the typed entry. Class IDs, `Meta`
   singletons and class metadata do not change.
5. **Callers.** The two direct callers in `AoWE.cs` (`TPadControl.Create(this)` and
   `TFlagControl.Create(this)`) use `new`.

## Tests

In `src/Rtl.Tests` or the product tests, whichever already reaches `Aow.Units`, assert for each of
the four classes:

- exact runtime type and owner (null and non-null) through `new`, through `Meta.Create` on its
  class reference, through `TEObject.Copy`, and through the engine's creation by saved class ID
  (`CreateEObject`)
- the `TEObject` body runs once on a converted chain and once on a legacy chain (one test class
  on each side is enough)
- a binary read that fails after successful construction of one of the four (truncated stream)
  behaves as it does today: the same exception, and the owner's children afterwards as today. Pin
  today's behavior on main first, then keep it.
