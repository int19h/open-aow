## What to build

1. **Programs.** The transpiler handles a Delphi `program` (a probe is one): the main block
   becomes `public static void Main()` of a program class that runs `Startup.InitializeAll`, the
   block and `FinalizeAll` in the order Delphi does, with the program's own units transpiled
   beside it. `WriteLn` and `Write` to standard output map to a shim routine that writes bytes in
   code page 1252 and `CRLF`, as the Delphi console does. A probe directory with several programs
   (`init-order`) works as the runner already treats it.
2. **The runner's transpile step.** `run.py` gains a mode `--transpiled` (and `--all` for both
   sides) that, per probe, runs the transpiler's `emit` on the probe into
   `tests/probes/generated/<name>/`, writes a small `.csproj` there referencing
   `D:\git\open-aow\src\Rtl\Aow.Rtl.csproj` (and `Aow.Generated` only if a probe uses Engine),
   builds it, runs it, captures standard output, converts CRLF to LF, and compares with
   `expected/<name>.txt` through the existing `--compare` logic. One line per probe: `match`,
   `DIFF <first differing line with both texts>`, or `FAILED <stage>: <reason>`. Exit code 0 when
   every probe matches.
3. **The asm-stubs probe.** `tests/probes/asm-stubs.pas` as `transpiler.md` section 8.2 describes:
   it calls each `bitop`, `fill` and `hex-coords` routine of the transpile set (the list is in
   `D:\git\open-aow-private\data\asm-routines.json`, by kind) on a battery of inputs including the
   edge cases section 8.2 names, under DCC32, with the units that declare them on the probe's
   search path (read-only from `D:\git\aow\src\delphi3`, compiled into `tests/probes/build/`).
   Record it like the other probes. Its transpiled side compares the overrides in
   `D:\git\open-aow\src\Overrides` for the Engine routines now. The routines of units not yet
   emitted (HSEngine, AoWEPACK, GFXE) are recorded on the Delphi side and listed as pending on the
   C# side, with a line per routine in the runner's output.
4. **Fixes.** Every probe mismatch is a transpiler or shim bug until shown otherwise. Fix the
   transpiler (never the generated output) or the shim, rerun, and keep going until every probe
   matches. If a mismatch comes from a mapping the specification prescribes, stop on that probe,
   keep the evidence (the Delphi line, the C# line, the mapping), and report it as a proposed
   specification change instead of working around it.
